## Implementation Phases (input to /ss:tasks)

**Phase A — Skeleton that runs (build system first, riskiest external dependency)**
1. Root/settings restructure; `:core` `:desktop` modules; LibGDX 1.14.2 wired; DesktopLauncher opens 1280×720 window with empty Game. Gate: `gradlew desktop:run` shows a window; `gradlew test` passes (empty).
2. `:android` module: AGP 9.0.0, manifest landscape, launcher delegating to shared Game. Gate: `gradlew android:assembleDebug` produces APK. (R2 risk lands here — resolve AGP/Gradle/minSdk friction NOW, not at the end.)

**Phase B — Pure engine + tests (no rendering, cheap iteration)**
3. TennisScore + TiebreakState per contract; full unit tests (contract invariants 1–8).
4. GestureClassifier + GestureTuning per contract; synthetic-trace tests including false-positive guard.
5. CourtGeometry, BallSimulator (2.5D, fixed timestep, spin bounce behavior), range/power-scaling rules; tests for in/out, bounce, range miss.
6. ServeState machine (aim window/power/accuracy/faults) with derived speed/deviation/fault-margin math; tests. AiController with DifficultyTier params (empty-space targeting, spin read tiers); deterministic seeded tests.

**Phase C — Screens & flow**
7. SpriteProvider + placeholder textures; screen framework; MainMenu, Settings (match length), Circuit/Tournament stubs.
8. CharacterSelect (roster grid, padlock badge) + Unlock/Patreon-gate screen (Flow 2 steps 1–2, placeholder button); CourtSelect.
9. Score screen (set-by-set + W/L → main menu).

**Phase D — Match screen (integration)**
10. MatchController wiring engine pieces; HUD (score top-center, serve indicator top-left); ball/court/character rendering.
11. Input: VirtualJoysticks (touch) + desktop WASD/mouse mapping; serve meter interaction; gesture capture → classifier → shot execution.
12. AI opponent playing full points (serve sans meters, movement, shot selection vs Medium).

**Phase E — Verification & polish**
13. End-to-end demo pass on desktop (single-set for iteration, then full best-of-3 for DoD); tune GestureTuning + AI win/loss balance (Success Criteria 4–5); android APK re-verified; update tech-stack.md "Current build.gradle.kts state" (FR-055) and .gitignore (local.properties).

## Definition of Done (from spec)

1. `gradlew desktop:run`: full demo flow per SPEC.md Success Criteria, best-of-3 match completes to Score screen.
2. `gradlew android:assembleDebug`: APK builds.
3. `gradlew test`: green, including scoring + gesture contract suites.
4. All four shot types producible; out-of-range misses; Medium AI winnable and losable.
